# Конспект по проекту «Конвертер валют»

Подробный разбор текущего кода Flutter-приложения: назначение файлов, связи между ними, конструкции Dart и Flutter, поток запроса к API, обработка ошибок и подсказки для самостоятельных изменений.

> Конспект соответствует состоянию проекта на 9 октября 2026 года. Если код изменится, некоторые фрагменты и объяснения могут потребовать обновления.

## 1. Что делает приложение

Пользователь вводит сумму, выбирает исходную и целевую валюты, затем нажимает кнопку «Перевести». Приложение получает курс у Frankfurter, умножает на него сумму и отображает сумму, курс и дату.

Сейчас приложение использует такую цепочку:

```text
Пользователь
    ↓
ConverterScreen (виджеты и ввод)
    ↓ действие пользователя
ConverterState (выбор валют, загрузка, результат, ошибки)
    ↓ запрос нужных данных
CurrencyRepository (источник данных для состояния)
    ↓ HTTP-операция
CurrencyApi (запрос и JSON)
    ↓ преобразование
ExchangeRate (типизированные курс и дата)
```

Есть и обратный путь для результата:

```text
ExchangeRate → CurrencyRepository → ConverterState
             → ListenableBuilder → ConverterScreen → экран
```

### Назначение файлов

| Файл | Ответственность |
|---|---|
| `lib/main.dart` | Запускает приложение и собирает зависимости в одну цепочку. |
| `lib/models/exchange_rate.dart` | Описывает курс и дату; проверяет JSON-поля и создаёт модель. |
| `lib/services/currency_api.dart` | Выполняет HTTP GET, задаёт тайм-аут, проверяет статус и разбирает JSON. |
| `lib/repositories/currency_repository.dart` | Предоставляет состоянию способ запросить курс, скрывая детали API-клиента. |
| `lib/state/converter_state.dart` | Хранит изменяемое состояние конвертера и выполняет логику конвертации. |
| `lib/widgets/converter_screen.dart` | Рисует экран и передаёт действия пользователя в `ConverterState`. |
| `pubspec.yaml` | Содержит зависимости проекта, в частности пакет `http`. |
| `pubspec.lock` | Фиксирует конкретные версии пакетов; обычно обновляется Flutter автоматически. |
| `android/app/src/main/AndroidManifest.xml` | Объявляет разрешение Android на доступ в интернет. |

Файлы `repositories` и `state` добавлены, чтобы разделить роли кода. Репозиторий пока тонкий: он просто передаёт запрос API-клиенту. Это нормально для учебного проекта; туда можно добавить кэш или другой источник курсов позже.

## 2. Запуск приложения — `lib/main.dart`

Текущий код:

```dart
import 'package:currency_converter/widgets/converter_screen.dart';
import 'package:flutter/material.dart';

import 'repositories/currency_repository.dart';
import 'services/currency_api.dart';

void main() {
  runApp(const MyApp());

  @override
  State<MyApp> createState() => _MyAppState();
```

### Импорты

- `converter_screen.dart` нужен, чтобы открыть экран конвертера.
- `material.dart` — библиотека Flutter с интерфейсными виджетами и темой.
- `currency_repository.dart`, `currency_api.dart`, `converter_state.dart` нужны здесь для сборки цепочки объектов.
- Импорт вида `package:currency_converter/...` использует имя пакета из `pubspec.yaml`.
- Импорты вида `'state/...'` — относительные пути от `lib/main.dart`.

### Функция `main`

```dart
void main() {
  runApp(const MyApp());
}
```

- `void` означает, что функция ничего не возвращает.
- `main()` — точка входа Dart-приложения.
- `runApp(...)` — функция Flutter, помещающая корневой виджет на экран.
- `const MyApp()` создаёт неизменяемый корневой виджет. `const` позволяет Flutter переиспользовать такие объекты, если это возможно.

### `MyApp` и `_MyAppState`

- `StatefulWidget` выбран потому, что объект состояния конвертера должен жить, пока запущено приложение.
- `createState()` создаёт `_MyAppState`, где хранится экземпляр `converterState`.
- Начальный вызов

  ```dart
  ConverterState(CurrencyRepository(CurrencyApi()))
  ```

  собирает зависимости изнутри наружу: сначала создаётся `CurrencyApi`, передаётся в `CurrencyRepository`, а репозиторий передаётся в `ConverterState`.
- `final converterState` создаётся один раз для этого состояния приложения и далее не заменяется.
- `dispose()` освобождает `ChangeNotifier`. `super.dispose()` завершает очистку базового класса Flutter.

### `build`

- `build(BuildContext context)` строит или перестраивает интерфейс.
- `MaterialApp` создаёт приложение Material.
- `title` — название приложения.
- `ThemeData` задаёт общую тему: Material 3, зелёный акцент и светлый фон.
- `home: ConverterScreen(state: converterState)` открывает экран и передаёт ему состояние. Экрану не нужно знать, как были созданы API-клиент и репозиторий.

## 3. Модель курса — `lib/models/exchange_rate.dart`

Текущий код:

```dart
class ExchangeRate {
  final double rate;
  final String date;

  ExchangeRate({required this.rate, required this.date});

  factory ExchangeRate.fromJson(Map<String, dynamic> json) {
    final rate = json['rate'];
    final date = json['date'];

    if (rate is! num || date is! String) {
      throw const FormatException('Неверный формат курса');
    }

    return ExchangeRate(rate: rate.toDouble(), date: date);
  }
}
```

- `class ExchangeRate` объявляет свой тип данных.
- `final double rate` — курс как дробное число.
- `final String date` — дата курса как текст.
- `required` в конструкторе означает, что оба параметра обязательны.
- `factory` обозначает конструктор, который может выполнять логику и вернуть созданный объект. Здесь он разбирает значения из JSON.
- `Map<String, dynamic>` — словарь, где ключи являются строками, а тип значений заранее не известен.
- `json['rate']` и `json['date']` достают значения по именованным ключам.
- `rate is! num` проверяет, что курс не является числом; `date is! String` проверяет, что дата не является строкой. `||` означает «или».
- `throw const FormatException(...)` прекращает преобразование и сообщает вызывающему коду, что данные не соответствуют ожиданиям.
- Если данные правильные, `rate.toDouble()` приводит число к `double`, а `return ExchangeRate(...)` создаёт и возвращает типизированную модель.

Поля `rate` и `date` соответствуют части JSON-ответа API. Другие возможные поля ответа модель пока игнорирует.

## 4. HTTP и JSON — `lib/services/currency_api.dart`

Текущий код:

```dart
import 'dart:convert';

import 'package:http/http.dart' as http;

import '../models/exchange_rate.dart';

class CurrencyApi {
  Future<ExchangeRate> getRate(String from, String to) async {
    final url = Uri.parse(
      'https://api.frankfurter.dev/v2/rate/${from.toLowerCase()}/${to.toLowerCase()}',
    );
    final response = await http.get(url).timeout(const Duration(seconds: 10));

    if (response.statusCode == 200) {
      final json = jsonDecode(response.body) as Map<String, dynamic>;
      return ExchangeRate.fromJson(json);
    } else {
      throw Exception('Не удалось получить курс');
    }
  }
}
```

### Импорты

- `dart:convert` — встроенная библиотека Dart для кодирования и разбора JSON.
- `package:http/http.dart as http` — внешний пакет `http`; через `http` вызываем функцию `get`.
- `exchange_rate.dart` — модель, в которую будет преобразован ответ.

### Функция `getRate`

- `Future<ExchangeRate>` говорит, что функция позже вернёт `ExchangeRate`.
- `async` разрешает использовать внутри `await`.
- `from` и `to` — строковые коды исходной и целевой валют.
- `Uri.parse(...)` создаёт объект URL из строки.
- `${...}` вставляет значение внутрь строки. `toLowerCase()` переводит коды в нижний регистр для пути запроса.
- `http.get(url)` отправляет HTTP GET-запрос.
- `await` ждёт ответ, но не блокирует основной поток интерфейса.
- `.timeout(const Duration(seconds: 10))` прекращает ожидание, если сервер не ответил за 10 секунд. `Duration` — встроенный тип Dart для промежутков времени.
- `response` — объект ответа с кодом статуса, заголовками и телом.
- `response.statusCode == 200` проверяет успешный HTTP-ответ.
- `response.body` содержит JSON как текст.
- `jsonDecode(...)` разбирает JSON-текст в значения Dart.
- `as Map<String, dynamic>` утверждает, что корнем JSON является объект-словарь. Если пришёл список или строка, приведение типа завершится ошибкой.
- `ExchangeRate.fromJson(json)` проверяет ключи и преобразует словарь в модель.
- `else` срабатывает при HTTP-статусе, отличном от 200.
- `throw Exception(...)` передаёт ошибку выше — её перехватит `ConverterState`.

Ошибки уровня сети и тайм-аута также возникают как исключения. В этом классе они специально не перехватываются, чтобы состояние могло решить, как их показать.

## 5. Репозиторий — `lib/repositories/currency_repository.dart`

Текущий код:

```dart
import '../models/exchange_rate.dart';
import '../services/currency_api.dart';

class CurrencyRepository {
  final CurrencyApi api;

  CurrencyRepository(this.api);

  Future<ExchangeRate> getRate(String from, String to) {
    return api.getRate(from, to);
  }
}
```

- Репозиторий импортирует модель, которую возвращает, и API-клиент, откуда пока получает данные.
- `final CurrencyApi api` хранит ссылку на клиент API.
- `CurrencyRepository(this.api)` — конструктор с сокращённой записью: переданное значение сразу присваивается полю `api`.
- `getRate` предоставляет верхним слоям понятный способ запросить курс.
- `return api.getRate(from, to)` передаёт вызов API-клиенту и возвращает его `Future<ExchangeRate>`.

Сейчас репозиторий — тонкая прослойка. Его польза в том, что `ConverterState` зависит от понятия «получить курс», но не обязан знать, как именно он получен. Позже вместо HTTP можно добавить локальный кэш или другой источник, меняя в основном репозиторий.

## 6. Логика и состояние — `lib/state/converter_state.dart`

Текущий код:

```dart
import 'package:flutter/material.dart';

import '../models/exchange_rate.dart';
import '../repositories/currency_repository.dart';

class ConverterState extends ChangeNotifier {
  final CurrencyRepository repository;

  ConverterState(this.repository);

  String fromCurrency = 'EUR';
  String toCurrency = 'RUB';
  bool isLoading = false;
  String? error;
  ExchangeRate? exchangeRate;
  double? convertedAmount;

  void setFromCurrency(String currency) {
    fromCurrency = currency;
    _clearResult();
  }

  void setToCurrency(String currency) {
    toCurrency = currency;
    _clearResult();
  }

  void swapCurrencies() {
    final oldCurrency = fromCurrency;
    fromCurrency = toCurrency;
    toCurrency = oldCurrency;
    _clearResult();
  }

  void _clearResult() {
    error = null;
    exchangeRate = null;
    convertedAmount = null;
    notifyListeners();
  }

  Future<void> convert(String amountText) async {
    final amount = double.tryParse(amountText.replaceAll(',', '.'));

    if (amount == null) {
      error = 'Введите сумму';
      notifyListeners();
      return;
    }
    if (amount < 0) {
      error = 'Сумма отрицательная';
      notifyListeners();
      return;
    }

    isLoading = true;
    error = null;
    exchangeRate = null;
    convertedAmount = null;
    notifyListeners();

    try {
      exchangeRate = await repository.getRate(fromCurrency, toCurrency);
      convertedAmount = amount * exchangeRate!.rate;
    } on FormatException {
      error = 'Сервер прислал данные в неверном формате';
    } catch (_) {
      error = 'Не удалось загрузить курс. Проверьте интернет.';
    }

    isLoading = false;
    notifyListeners();
  }
}
```

### Класс и поля

- `ChangeNotifier` — класс Flutter, который умеет уведомлять слушателей об изменениях.
- `repository` — источник курса для состояния. Состояние не обращается к `CurrencyApi` напрямую.
- Конструктор сохраняет переданный репозиторий.
- `fromCurrency`, `toCurrency` — выбранные коды валют.
- `isLoading` — показывает, выполняется ли запрос.
- `String? error` — `?` означает, что поле может содержать строку или `null`. `null` здесь значит «ошибки нет».
- `ExchangeRate? exchangeRate` — модель курса либо `null`, если курса ещё нет.
- `double? convertedAmount` — вычисленный результат либо `null`.

### `setFromCurrency` и `setToCurrency`

Каждый метод записывает новое значение валюты, затем вызывает `_clearResult()`. Старый ответ относится к предыдущей паре валют, поэтому его нужно убрать.

### `swapCurrencies`

- Сохраняет исходную валюту в `oldCurrency`.
- Переносит целевую валюту в исходную.
- Возвращает сохранённое значение в целевую.
- Очищает старый результат.

Временная переменная нужна, потому что при простом присваивании первое значение было бы потеряно.

### `_clearResult`

- Начальный символ `_` в Dart делает имя приватным в пределах библиотеки/файла импорта; метод предназначен для внутреннего использования.
- Сбрасывает ошибку, модель курса и рассчитанную сумму.
- `notifyListeners()` сообщает слушателям: «состояние изменилось, перестройте интерфейс».

### `convert`

- Принимает текст из поля суммы. Сам контроллер ввода остаётся на экране, но проверка и вычисление происходят в состоянии.
- `replaceAll(',', '.')` заменяет десятичную запятую точкой.
- `double.tryParse(...)` пытается превратить текст в число. Если не получилось, возвращает `null`, не выбрасывая ошибку.
- При пустой/нечисловой сумме ставится сообщение, отправляется уведомление и `return` прекращает функцию.
- Отрицательная сумма обрабатывается похожим образом.
- Перед запросом `isLoading` устанавливается в `true`, предыдущие ошибка и результат сбрасываются, вызывается `notifyListeners()`.
- В `try` состояние запрашивает курс через репозиторий и умножает сумму на числовое поле модели.
- `exchangeRate!` — утверждение Dart-разработчика, что значение не `null`. Оно присвоено строкой выше, если запрос завершился успешно.
- `on FormatException` отдельно обрабатывает невалидный JSON или неправильные типы полей модели.
- `catch (_)` ловит остальные исключения, например сетевую ошибку, тайм-аут или HTTP-ошибку. `_` значит, что текст исходного исключения здесь не используется.
- В конце `isLoading` выключается, и новое состояние рассылается слушателям.

Важно: приложение пока показывает одно общее сообщение для большинства сетевых ошибок. При желании можно позже отдельно различать тайм-аут, HTTP-ошибку и отсутствие интернета.

## 7. Интерфейс — `lib/widgets/converter_screen.dart`

Экран теперь передаёт действия в `ConverterState` и отображает его данные. В нём нет HTTP-запросов и формулы обработки API.

Полный текущий код экрана:

```dart
import 'package:flutter/material.dart';

import '../state/converter_state.dart';

class ConverterScreen extends StatefulWidget {
  const ConverterScreen({super.key, required this.state});

  final ConverterState state;

  @override
  State<ConverterScreen> createState() => _ConverterScreenState();
}

              ),
              NavigationDestination(
                icon: Icon(Icons.bookmark_border),
                label: 'Избранное',

              NavigationDestination(
                icon: Icon(Icons.history),
```

### Объявление экрана

- Импорт `material.dart` даёт интерфейсные виджеты.
- Импорт `converter_state.dart` позволяет экрану читать состояние и вызывать его методы.
- `ConverterScreen extends StatefulWidget` — экрану нужно хранить контроллер поля суммы.
- Конструктор требует `state`; экран не создаёт внутри себя API и репозиторий.
- `final ConverterState state` хранит переданное состояние.
- `createState()` создаёт объект с контроллером и разметкой.
- `amountController` управляет текстом суммы и начинает с `100`.
- `currencies` — коды для пунктов двух выпадающих списков.
- `dispose()` освобождает `TextEditingController`. Сам `ConverterState` освобождает родительское приложение в `main.dart`.

### Метод `build`

- `build(BuildContext context)` строит дерево интерфейса.
- Локальные `const` цвета помогают не повторять цветовые коды в каждом виджете.
- `ListenableBuilder` слушает `widget.state`. Когда состояние вызывает `notifyListeners()`, Flutter выполняет его `builder` снова.
- `final state = widget.state` — короткое локальное имя для передачи методов и чтения полей состояния.
- `resultText` готовит текст результата. Сначала это заглушка `— —`; при загрузке это `Загрузка...`; если есть ошибка — выводится она; при успехе собираются сумма, курс и дата.
- `!` после nullable-полей означает «я уверен, что здесь не `null`». Ветка кода предварительно проверила наличие курса; результат также вычисляется в том же успешном сценарии.

### Основные виджеты

- `Scaffold` задаёт структуру страницы.
- `AppBar` рисует верхнюю панель с названием.
- `SingleChildScrollView` позволяет прокручивать содержимое, если оно не помещается по высоте.
- `Padding` создаёт поля по 20 пикселей вокруг содержимого.
- `Column` ставит дочерние элементы вертикально; `crossAxisAlignment.start` выравнивает их по левому краю.
- `TextField` — поле суммы. `controller` даёт прочитать введённую строку; `keyboardType` просит числовую клавиатуру; `suffixText` показывает текущую исходную валюту.
- `InputDecoration` настраивает заполнение и границу поля. В текущем коде у границы указано `width: 20`; это очень толстая линия. Для обычной тонкой рамки обычно используют небольшую ширину или `BorderSide.none`.
- `SizedBox(height: ...)` добавляет вертикальный промежуток.
- `Row` ставит выбор валют в один ряд.
- `Expanded` делит свободную ширину строки между левым и правым выпадающими списками.
- `DropdownButton<String>` — выпадающий список строковых кодов валют.
- `currencies.map(...)` превращает каждый код в `DropdownMenuItem`. `.toList()` собирает полученные пункты в список, который нужен виджету.
- `onChanged` вызывается при выборе валюты. Проверка `value != null` защищает от попытки записать отсутствующее значение. Затем вызывается `state.setFromCurrency` или `state.setToCurrency`; интерфейс сам себя не обновляет напрямую.
- `IconButton` вызывает `state.swapCurrencies`. Во время загрузки `onPressed` равен `null`, поэтому кнопка выключена.
- `FilledButton` запускает `state.convert(amountController.text)`. Во время запроса он тоже отключён.
- `FilledButton.styleFrom(...)` задаёт цвет кнопки.
- `Container` создаёт карточку результата с фоном, отступом и скруглением.
- В карточке `Text(resultText)` показывает рассчитанную строку, а следующий `Text` показывает направление обмена.
- `NavigationBar` рисует нижнее меню с четырьмя пунктами. Сейчас выбран пункт с индексом `0` («Обмен»). Другие пункты пока только показывают `SnackBar` — небольшое всплывающее сообщение; отдельных экранов для них ещё нет.
- `ScaffoldMessenger.of(context)` находит область показа сообщений приложения.

## 8. Пакет HTTP и разрешение интернета

### `pubspec.yaml`

В секции `dependencies` находятся примерно такие записи:

```yaml
dependencies:
  flutter:
    sdk: flutter
  cupertino_icons: ^1.0.8
  http: ^1.6.0
```

- `dependencies` — список библиотек, нужных приложению.
- `flutter: sdk: flutter` указывает на сам Flutter SDK.
- `cupertino_icons` — пакет значков Cupertino из шаблона проекта.
- `http: ^1.6.0` — внешний пакет для HTTP-запросов. `^` разрешает обновления совместимых версий в пределах правила Pub.

Добавлять/обновлять пакет обычно нужно командой:

```bash
flutter pub add http
```

После неё Flutter меняет `pubspec.yaml` и `pubspec.lock`. `pubspec.lock` хранит точные разрешённые версии зависимостей, чтобы проект собирался воспроизводимо. Обычно его вручную не редактируют.

### `AndroidManifest.xml`

В начале `android/app/src/main/AndroidManifest.xml` добавлено:

```xml
<uses-permission android:name="android.permission.INTERNET" />
```

Эта строка объявляет Android, что приложению нужен доступ в интернет. Без разрешения HTTP-запрос из Android-приложения может не пройти.

## 10. Асинхронность и изменение экрана

`Future` представляет значение, которое будет доступно позже. Получение данных из интернета нельзя считать мгновенным. Поэтому `CurrencyApi.getRate`, `CurrencyRepository.getRate` и `ConverterState.convert` возвращают `Future`.

Последовательность при нажатии на кнопку:

1. Экран передаёт текст суммы в `state.convert(...)`.
2. Состояние проверяет ввод и включает `isLoading`.
3. `notifyListeners()` вызывает обновление `ListenableBuilder`; на экране появляется «Загрузка...», элементы выбора и кнопка отключены.
4. Состояние вызывает репозиторий, тот вызывает API-клиент.
5. API-клиент выполняет GET и ждёт ответ до 10 секунд.
6. Ответ превращается в `ExchangeRate`; состояние вычисляет сумму.
7. Состояние выключает `isLoading` и вызывает `notifyListeners()` ещё раз.
8. `ListenableBuilder` перестраивает экран с результатом либо ошибкой.

Сетевой запрос не размещён в `build()`: иначе каждое перестроение экрана могло бы отправлять новый запрос.

## 11. Обработка ошибок

| Ситуация | Где возникает | Как обрабатывается сейчас |
|---|---|---|
| Пустое или нечисловое поле | `double.tryParse` в `ConverterState` | Пишется «Введите сумму». |
| Отрицательная сумма | Проверка `amount < 0` | Пишется «Сумма отрицательная». |
| Ответ без HTTP-кода 200 | `CurrencyApi` | Выбрасывается `Exception`, состояние показывает общее сообщение про загрузку/интернет. |
| Нет интернета / DNS / соединение оборвалось | `http.get` | Исключение перехватывается общим `catch` в состоянии. |
| Сервер не ответил за 10 секунд | `.timeout(...)` | Возникает ошибка Future, она перехватывается общим `catch`. |
| JSON синтаксически неправильный | `jsonDecode` | Может возникнуть `FormatException`, показывается ошибка формата. |
| Нет `rate`/`date` или тип неверный | `ExchangeRate.fromJson` | Выбрасывается `FormatException`, показывается ошибка формата. |
| JSON корневого типа не объект | `as Map<String, dynamic>` | Возникает ошибка типа; попадает в общий `catch`, показывается общее сообщение. |

Сейчас все не-`FormatException` объединены общим сообщением. Это упрощает код, но не различает отсутствие интернета, тайм-аут и HTTP-ошибку. Для лабораторной можно при желании обработать их раздельно.

## 12. Как самостоятельно вносить правки

### Изменить список валют

Поменяй список `currencies` в `converter_screen.dart`. Например, добавь `'CAD'`. Убедись, что выбранный по умолчанию код тоже присутствует в списке и поддерживается API.

### Изменить начальную пару валют

Измени `fromCurrency` и `toCurrency` в `converter_state.dart`. После изменения проверь, что оба кода есть в списке на экране.

### Изменить тайм-аут

В `currency_api.dart` поменяй `Duration(seconds: 10)` на нужное количество секунд.

### Добавить поле из JSON

Если понадобится ещё одно поле ответа:

1. Добавь типизированное поле в `ExchangeRate`.
2. Проверь наличие и тип поля в `fromJson`.
3. Добавь значение в конструктор модели.
4. При необходимости покажи его в `converter_screen.dart`.

### Сменить API

Старайся менять URL и разбор ответа в `CurrencyApi`. Если новая модель или поля отличаются, обнови `ExchangeRate` и тестируй правильный ответ. `ConverterState` должен по-прежнему получать модель через `CurrencyRepository`.

### Изменить текст ошибки

Тексты для ввода, сети и формата ответа находятся в `converter_state.dart`. UI отображает готовое значение `state.error`.

### Добавить новую функцию

Сначала реши, к какой ответственности она относится:

- HTTP, URL и ответ сервера → `CurrencyApi`.
- выбор источника, объединение, кэш → `CurrencyRepository`.
- загружено/ошибка/выбор валют/расчёт → `ConverterState`.
- расположение, цвет, подписи, кнопки → `ConverterScreen`.
- поля данных API → `ExchangeRate`.

## 13. Важные ограничения текущей версии

- В нижнем меню видны «Курсы», «Избранное» и «История», но отдельные экраны ещё не созданы.
- Список валют задан вручную, а не загружается из API.
- Репозиторий пока только передаёт запрос дальше; кэширования нет.
- Данные курса не сохраняются офлайн.
- Тайм-аут есть, но отдельного текста именно для тайм-аута пока нет.
- При одинаковой исходной и целевой валюте запрос всё равно отправляется в API.
- Валюта и сумма не сохраняются между запусками приложения.
